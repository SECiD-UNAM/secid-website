## Phase 4 — seguridad / abuse

### §10.3 CORS bypass — ❌ ENCONTRADO, ✅ ARREGLADO

\`\`\`bash
curl -X OPTIONS https://us-central1-secid-org.cloudfunctions.net/requestAlternateEmail \
 -H "Origin: https://attacker.secid.mx" -i

# HTTP 204

# access-control-allow-origin: https://attacker.secid.mx ← bypass aceptado!

\`\`\`

**Causa raíz**: el regex `/^https:\/\/(?:[a-z0-9-]+\.)?secid\.mx$/` que llamé "anchored" en S1 sí ancla el scheme + host, pero el grupo de subdominio opcional `(?:[a-z0-9-]+\.)?` matchea **cualquier** subdominio de primer nivel — incluyendo `attacker.secid.mx`.

**Fix shipeado** (`7b7c49f`): allowlist literal de los 5 hosts conocidos (apex, www., beta.) + regex de loopback localhost/127.0.0.1. Nuevos environments necesitan add explícito.

**Re-test pendiente**: confirmar que después del deploy de `7b7c49f` la curl de arriba retorna 403/sin Access-Control-Allow-Origin.
