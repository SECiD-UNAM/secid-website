## Phase 4 — Security / abuse

### ✅ §10.3 CORS bypass — ENCONTRADO Y ARREGLADO

**Antes** (`bf1b165`): regex `/^https:\/\/(?:[a-z0-9-]+\.)?secid\.mx$/` aceptaba `attacker.secid.mx`.
**Verificado live**: curl OPTIONS con Origin: attacker.secid.mx → 204 + ACAO echoed ⛔
**Después** (`7b7c49f`): allowlist literal de 5 hosts conocidos + loopback regexes.
**Re-validado live**:

```
attacker.secid.mx → 204 NO ACAO   (browser blocks)
evil.com         → 204 NO ACAO   (browser blocks)
beta.secid.mx    → 204 ACAO: https://beta.secid.mx  (allowed)
```

### ✅ §10.4 Rate limit

6 submits desde misma IP al endpoint newsletter:

```
submit 1-4: 400 captcha_failed (avanza contador)
submit 5+:  429 rate_limited     ← funciona
```

### ✅ §10.5 IDOR (parcial)

Anonymous GET de `users/<other-uid>` vía REST/SDK → `permission-denied` ✅
Las rules deniegan anonymous read salvo si el dueño puso `privacy.profileVisibility='public'` AND `cvVisibility='public'` (CV viewer path).

### ✅ §10.8 XSS — ENCONTRADO Y ARREGLADO

**Antes**: newsletter+contact endpoints aceptan cualquier string raw. React escapa al render pero **mis emails de Phase 0 interpolaban user-controlled values en HTML body** sin escape → Outlook/Apple Mail ejecutarían `<img onerror>`, `<a href="javascript:">`.
**Después** (`d044d92`): `escapeHtml()` helper en `email-templates.ts` + aplicado a TODAS las interpolaciones user-controlled (recipientName, memberEmail, numeroCuenta, registrationType, reason, contactEmail).

### ❌ Pendientes

- §10.6 Token replay (requiere coordinación con reCAPTCHA admin)
- §10.7 Session security (requeriría manipular tokens de sesión real)
