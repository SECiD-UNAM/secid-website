# Known issue: remaining `npm audit` advisories (2026-10-18)

**Status:** Open — tracked. Everything that could be fixed without a
major-version bump was applied in `chore/npm-audit-safe-fixes` (PR #92).
ROADMAP E16 phase 1 (2026-10-19, PR #133) then
took the two majors that were isolated enough to do on their own: Vitest
1 → 5 (dev-only, root) and `firebase-admin` 13 → 14 (Cloud Functions).
**Severity:** Mixed. The only advisories that still touch the production
runtime are the Astro / `@astrojs/node` ones (need Astro 7). Everything
else is build-time or dev-only tooling, plus the `googleapis` → `uuid`
chain in Cloud Functions (needs `googleapis` 186).

Dependabot reports more alerts than `npm audit` because it counts one
alert per advisory per lockfile; `npm audit` counts one entry per
package. Both lists are the same set of packages.

## What was applied (non-breaking)

- `npm audit fix` (no `--force`) at the root and in `functions/`.
- Root `overrides` (all stay inside the dependent's major):
  - `sharp: ^0.35.5` — Astro 6 declares `^0.34.0`, Astro 7 declares
    `^0.35.4`; the build (image compression via `@playform/compress`)
    was verified with 0.35.5.
  - `svgo: ^4.1.0` — `@playform/compress` pins 4.0.2.
  - `@grpc/grpc-js: ^1.14.6` — `@firebase/firestore` declares `~1.9.0`.
    The two advisories are gRPC _server_-side only; the Firestore client
    uses the gRPC client API, which is stable across 1.x. Same version
    `firebase-admin` already uses in `functions/`.
- `functions/` `overrides`: `qs: ^6.16.1` (Express 4 pins `~6.14.0`).
- `functions/`: removed the unused `firebase-functions-test`
  devDependency (no imports anywhere; it pulled `jest` + `ts-deepmerge`,
  which accounted for 21 advisories).
- `functions/`: `firebase-functions` pinned to `7.3.0` (was `^7.0.0`,
  lock had 7.2.2). 7.3.0 is the last release on Express 4; 7.3.2 and
  7.4.0 switch to Express `^5.2.1`, which changes `req.query` parsing
  and routing semantics, so that bump is deliberately left for a
  follow-up (see below).

## E16 phase 1 — what it fixed (2026-10-19)

- Root: `vitest` / `@vitest/ui` / `@vitest/coverage-v8` 1.6.1 → 5.0.5, which
  drops `vite` 5 (→ 7.3, the same major Astro 6 bundles, so there is now a
  single `vite` in the tree), `vite-node` and `tinypool`. That is 6 entries
  (4 critical, 1 high, 1 moderate) gone — the only remaining critical is
  `astro` itself. `@types/node` went 20 → 22 to satisfy Vitest's peer
  range; Node 22.12 (`.nvmrc`, CI) already meets Vitest 5's engine floor
  (`^22.12.0 || ^24 || >=26`).
- `functions/`: `firebase-admin` 13.10 → 14.5, which pulls
  `@google-cloud/firestore` 8 / `@google-cloud/storage` 8 / `google-gax` 5
  and removes the whole `retry-request` / `teeny-request` / `uuid` 9 chain
  (6 moderate entries). `firebase-admin` 14 deletes the namespaced API
  (`admin.firestore()`, `admin.auth()`, `admin.app()`), so every Cloud
  Function now uses the modular entry points (`getFirestore()`, `getAuth()`,
  `getApp()`); the `firebase-functions` 7.3.0 pin is untouched (it already
  accepts `firebase-admin ^14`).
- Not changed on purpose: `tailwindcss` 4, `astro` 7 / `@astrojs/node` 11
  (phase 2, see ROADMAP E16), and the small follow-ups below.

## Deferred on purpose

- **Phase 2 of ROADMAP E16** — `astro` 7 + `@astrojs/node` 11 (the only
  production-runtime advisories left) and `tailwindcss` 4 (clears the
  `braces`/`chokidar`/`postcss-selector-parser` family). Both are separate
  decisions: they need the full e2e suite to be blocking first.
- `firebase-functions` 7.3.2 / 7.4.0 — moves to Express 5. Upgrade in
  its own PR and re-test the `onRequest` handlers that read `req.query`.
- Root `firebase` was bumped 12.13.0 → 12.19.0 by `npm audit fix`
  (minor); its remaining advisory entries disappeared with the
  `@grpc/grpc-js` override.
