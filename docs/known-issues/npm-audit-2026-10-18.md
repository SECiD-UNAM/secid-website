# Known issue: remaining `npm audit` advisories (2026-10-18)

**Status:** Open — tracked. Everything that could be fixed without a
major-version bump was applied in `chore/npm-audit-safe-fixes`.
**Severity:** Mixed. The only advisories that touch the production
runtime are the Astro / `@astrojs/node` ones (need Astro 7) and the
`firebase-admin`/`googleapis` `uuid` chain in Cloud Functions (needs
`firebase-admin` 14 / `googleapis` 186). Everything else is build-time
or dev-only tooling.

Dependabot reports more alerts than `npm audit` because it counts one
alert per advisory per lockfile; `npm audit` counts one entry per
package. Both lists are the same set of packages.

## What was applied (non-breaking)

- `npm audit fix` (no `--force`) at the root and in `functions/`.
- Root `overrides` (all stay inside the dependent's major):
  - `sharp: ^0.35.5` — Astro 6 declares `^0.34.0`, Astro 7 declares
    `^0.35.4`; the build (image compression via `@playform/compress`)
    was verified with 0.35.5.
  - `svgo: ^4.1.0` — `@playform/compress` pins 4.0.2.
  - `@grpc/grpc-js: ^1.14.6` — `@firebase/firestore` declares `~1.9.0`.
    The two advisories are gRPC _server_-side only; the Firestore client
    uses the gRPC client API, which is stable across 1.x. Same version
    `firebase-admin` already uses in `functions/`.
- `functions/` `overrides`: `qs: ^6.16.1` (Express 4 pins `~6.14.0`).
- `functions/`: removed the unused `firebase-functions-test`
  devDependency (no imports anywhere; it pulled `jest` + `ts-deepmerge`,
  which accounted for 21 advisories).
- `functions/`: `firebase-functions` pinned to `7.3.0` (was `^7.0.0`,
  lock had 7.2.2). 7.3.0 is the last release on Express 4; 7.3.2 and
  7.4.0 switch to Express `^5.2.1`, which changes `req.query` parsing
  and routing semantics, so that bump is deliberately left for a
  follow-up (see below).
